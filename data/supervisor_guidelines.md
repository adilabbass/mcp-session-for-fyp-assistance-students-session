# Supervisor Expectations & Assessment Criteria

## Weekly meetings
- Come prepared with a written status update: what is done, what is pending,
  what is blocked.
- Bring evidence — a demo, a test run, or a link to a merged pull request.
  Verbal claims of progress are not accepted as evidence.
- Bring a short list of questions or decisions you need from the supervisor.

## Deliverables
- Requirements document (this brief), kept up to date.
- A working prototype demonstrable at each meeting from week 4 onward.
- A public issue tracker (GitHub Issues) that reflects real work.
- Final report and code walkthrough at end of semester.

## Assessment weight (indicative)
- Working software: 40%
- Documentation and process: 20%
- Individual contribution and viva: 30%
- Presentation: 10%

## Code quality
- Clear naming, small functions, no dead code.
- Tests for the core flows: search, issue, return, overdue report.
- No committed secrets. `.env.example` only.
